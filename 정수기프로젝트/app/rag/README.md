# RAG 자료와 갱신 방법

## 현재 검색 구성

- `approved/documents/`: 수신 자료에서 승인된 검색 Markdown 58개. 원문 바이트를 그대로 보존한다.
- `approved/manifest.json`: 승인 ID·문서 해시·적용 모델·사용 범위·출처 목록.
- `approved_loader.py`: 승인/해시 검사, 모델·용도 제한, 청크 구성. 현재 58개 문서에서 121개 청크를 구성한다.
- `retriever.py`: 기존 검수 청크 7개와 승인 청크 121개의 키워드·벡터 하이브리드 검색.
- `vector_index.py`: LangChain OpenAIEmbeddings와 로컬 Chroma. 공개 자료 128개 청크에서 검색용 구간 440개를 구성한다. 표준답변 질문을 별도 임베딩하고, 응답에는 원래의 질문·답변 전체를 반환한다.
- `reranker.py`: 유사도가 낮거나 후보 점수가 비슷할 때만 공개 후보의 질문·상황·참고 설명을 비교한다. RAG 내부의 제한된 모델 호출이며 업무 도구를 선택하는 별도 Agent가 아니다. 후보 ID 밖의 결과를 차단하고 검토된 후보를 일반 단어 일치가 다시 덮지 않게 한다.
- `app/backend/ai/runtime/rag/`: 로컬 Chroma와 활성 인덱스 지문. 개인 계약·대화·동의 토큰을 저장하지 않는다.
- `sync_approved.py`: 다음 수신 자료의 검증과 반영 도구. 수집 코드나 AI 검수 초안을 실행하지 않는다.

개인 계약 PDF·세션·권한 토큰은 공용 RAG에 넣지 않는다. 제품 가격·신규 요금·개인 비용 계산은 기존 전용 도구와 데이터로 관리한다. 공용 자료를 넣었다고 계산 요율이나 제품 가격을 자동으로 바꾸지 않는다.

## 사용 범위

출처와 적용 조건을 함께 반환한다. 한국소비자원 표준답변 43건은 질문과 답변을 같은 단위로 보존한다. HTML 표·TABLE_ROWS 셀 구조·코드 블록은 쪼개지 않는다. 과도하게 큰 구조는 잘라 쓰지 않고 검색 제외 목록에 표시한다.

한국소비자원·법령 저장 자료는 일반 상담 참고용이다. 현행 법령 확정 판단이나 LG 개인 해약금 계산 기준으로 사용하지 않는다. WD520·WU923 설명서의 승인된 장만 사용하며, 미승인 사용하기·문제해결 전체와 다른 모델의 버튼 누름 시간은 적용하지 않는다. 저장 본문 승인과 현재 홈페이지 재확인은 구분한다.

## 새 자료 적용

`02_팀공유_실행용`에서 가상환경을 활성화한 뒤 실행한다. `--source`는 압축을 푼 지식문서 폴더 경로이다.

```bash
python -m 정수기프로젝트.app.rag.sync_approved --source "/실제경로/03_지식문서"
```

먼저 검증만 한다. 원문·추출 본문·검색 문서의 해시, 승인 목록과 인덱스 후보의 일치를 검사한다. 성공했을 때 API 서버를 중지하고 아래 명령을 실행한 후 다시 시작한다.

```bash
python -m 정수기프로젝트.app.rag.sync_approved --source "/실제경로/03_지식문서" --apply
```

실패하면 기존 자료를 유지한다. 폴더 교체 중 동시 조회를 피하기 위해 적용 시 서버를 중지해야 한다. 수신 승인 기록의 `agent_index_updated`를 임의로 변경하지 않는다. 자체 반영 결과는 명령 출력으로 확인한다.

승인 ID가 바뀐 문서는 이전 모델 적용 정보를 자동 승계하지 않는다. 새 승인 범위와 적용 모델을 검토해 manifest의 models를 보완한 뒤 해당 모델 질문으로 테스트한다. 검색은 표현 변형과 긴 문서 순위에 한계가 있으므로 실제 질문으로 점검한다. 인덱스를 갱신하지 않으면 지문 불일치로 벡터 검색이 비활성화되고 키워드 검색으로 복구된다.

## 연결 흐름

고객 질문을 받은 LangChain Agent가 `search_contract_knowledge`를 선택하면 MCP가 검색을 수행한다. 상담 목적·보유 모델은 서버 문맥에서 전달하고, 최종 응답의 출처는 검증된 로컬 메타데이터로 재구성한다. n8n 수집 워크플로를 고객 상담 요청마다 실행하지 않는다.

## 벡터 인덱스 생성·상태 확인

실행용 폴더에서 가상환경 활성화 후 실행한다. `app/config/app.env`의 OPENAI_API_KEY를 사용한다. 별도의 Chroma 서버, 계정, n8n 연결은 필요 없다.

```powershell
python -m 정수기프로젝트.app.run rag-index
python -m 정수기프로젝트.app.run rag-status
```

문서 최초 반영 및 `sync_approved --apply` 후에는 `rag-index`를 실행한다. 공개 검수 본문만 OpenAI 임베딩 API로 전송하며 최초 구축에 API 사용량이 발생한다. 같은 자료·모델이면 다시 임베딩하지 않는다. 질의 시에는 검색 질문을 임베딩하지만 DB에 저장하지 않는다. 질문에도 불필요한 개인정보를 넣지 않는다.

대화 모델 선택(LLM_PROVIDER)과 임베딩 모델(RAG_EMBEDDING_MODEL)은 독립적이다. Anthropic으로 대화하더라도 검색에는 OPENAI_API_KEY가 필요하다. 임베딩 모델을 바꾸면 반드시 인덱스를 다시 만든다. 임베딩 장애·키 누락·인덱스 누락/지문 변경 시 기존 키워드 검색이 동작하며 `retrieval.mode`와 `vector_warning`으로 확인한다. 고객 답변에 내부 오류 문구를 붙이지 않는다. `RAG_SEARCH_MODE=keyword`로 명시적으로 원복할 수도 있다.

현재 후보는 승인·모델·목적·계약 전용 범위로 먼저 제한한다. Chroma 검색 필터와 원본 허용 목록 확인을 모두 거친다. 유효기간이 지난 행사에는 기존 만료 안내를 유지하고, 일반 법령을 개별 비용 계산 근거로 전환하지 않는다. 원문·표는 그대로 보존하고 임베딩용 구간만 별도로 나눈다.

공식 구현 참고: [LangChain Chroma](https://docs.langchain.com/oss/python/integrations/vectorstores/chroma), [OpenAI Embeddings](https://developers.openai.com/api/docs/guides/embeddings).

재검토 설정은 `RAG_RERANK=true`, `RAG_RERANK_MODEL=gpt-4.1-mini`이다. 재검토에는 공개 질문·허용된 공개 후보만 전달하고 답변·금액을 생성하지 않는다. 재검토 API 실패 시 원래 벡터 순위를 유지한다. `RAG_RERANK=false`로 비활성화할 수 있다. 문서의 A/S 약어는 검토 입력에서만 풀어 쓰고 원문은 바꾸지 않는다.

후보 재검토가 실행되면 추가 모델 사용량과 응답 시간이 발생한다. 검색 반환의 `retrieval.reranked`로 실행 여부를 구분한다. 응답·계약 금액·개인정보는 재검토 모델이 생성하거나 저장하지 않는다.
